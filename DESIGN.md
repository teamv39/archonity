# DESIGN.md — Спецификация интерфейса Archonity

> **Устарело.** Спецификация интерфейса под глобальный граф сервисов (ADR-001). Визуализатор под трассу сценария не переделан, см. [roadmap.md](docs/roadmap.md).

## 1. Назначение и предметное заземление (Subject Grounding)

Фронтенд **Archonity** — это прикладной инженерный инструмент (Workbench) для визуальной отладки реконструированного графа микросервисов, верификации доказательной базы рёбер (`evidence.json`) и демонстрации расчёта радиуса поражения (`blast_radius`).

* **Никакого маркетингового слоя:** приложение открывается сразу в рабочем экране анализа графа. Запрещены приветственные hero-секции, промо-карточки, лендинговые блоки и абстрактные иллюстрации.

* **Стилевая парадигма:** гибрид швейцарской модульной сетки (Swiss Grid) и высокоплотного инженерного инспектора (CAD / Profiling Tools) в **светлой теме**.

* **Первичный артефакт:** интерактивный ориентированный граф зависимостей, синхронизированный с табличным реестром рёбер и инспектором исходного кода.

## 2. Компоновка рабочего экрана (Viewport Layout)

Интерфейс строится как полноэкранное приложение (`100vw x 100vh`, `overflow-hidden`), разделённое линиями толщиной `1px` на 3 функциональные зоны без внешних отступов и «воздушных» карточек:

```
+-----------------------------------------------------------------------------------+
| [ARCHONITY] | Слой: [x] AST [x] CFG [x] ML [ ] TRANS | Порог p >= [0.72] | Сводка |
+-------------------------------------------------+---------------------------------+
|                                                 | ИНСПЕКТОР УЗЛА / РЕБРА          |
|                                                 | Выбрано: ts-order -> ts-station |
|                                                 | Тип: HTTP_CALL | Скор: 1.00     |
|                                                 +---------------------------------+
|              КАНВА ГРАФА (65% ширины)           | ДОКАЗАТЕЛЬСТВО (EVIDENCE LOG)   |
|       (Интерактивная топология сервисов,        | Источник: AST_EXACT             |
|        таблиц БД и очередей сообщений)          | Вызов: OrderServiceImpl.java:154|
|                                                 | Приём: StationController.java:39|
|                                                 | Шаблон: /api/v1/station/*       |
|                                                 +---------------------------------+
|                                                 | РЕЕСТР РЁБЕР / BLAST RADIUS     |
|                                                 | [Таблица всех связей / Узлов]   |
+-------------------------------------------------+---------------------------------+

```

1. **Верхняя панель управления (Control Bar, высота `40px`):**

   * Переключатели видимости слоёв по источникам: `AST_EXACT`, `CONFIG`, `ML_PREDICTED`, `TRANSITIVE`.

   * Ползунок отсечения вероятности ML-рёбер ($p_{\text{threshold}} \in [0.0, 1.0]$) с мгновенным пересчётом количества активных рёбер на экране.

   * Поиск по `node_id` / URL-шаблону и счётчики графа (`Nodes`, `Direct Edges`, `Transitive Edges`, `Dead Code Filtered`).

2. **Левая/Центральная зона — Канва графа (65% ширины):**

   * Векторное поле со светлой координатной сеткой (шаг `16px`, точки `#D6D3CD`).

   * Элементы управления масштабом, укладкой (Dagre / ELK иерархическая укладка слева направо или сверху вниз) и кнопка сброса фокуса.

3. **Правая зона — Инспектор и реестр доказательств (35% ширины, `border-l`):**

   * **Блок 1: Паспорт выбранного элемента.** При клике на ребро показывает: `source -> target`, тип связи, источник (`AST` / `CONFIG` / `ML`), файл, строку кода, нормализованный URL-шаблон и совпавшие DTO.

   * **Блок 2: Анализатор Blast Radius.** При клике на узел подсвечивает все прямо и транзитивно зависимые микросервисы (обратный обход графа) и выводит их плоским списком.

   * **Блок 3: Табличный реестр рёбер.** Плотная таблица всех рёбер с быстрой сортировкой по `confidence` и фильтрацией по типу.

## 3. Цветовая система (Light Engineering Tokens)

Строгая светлая тема на базе тёплой бумажно-серой подложки для снижения нагрузки на глаза при работе с графом и таблицами.

```
:root {
  /* Поверхности */
  --bg-canvas: #F7F6F2;        /* Подложка канвы графа */
  --bg-panel: #FFFFFF;         /* Фон инспектора и таблиц */
  --bg-subtle: #EFEDE8;        /* Шапки таблиц, неактивные вкладки, ховеры строк */
  --bg-selected: #E5E2DC;      /* Выделенная строка или активный контрол */

  /* Линии и рамки */
  --border-hairline: #D4D1C8;  /* Основная сетка интерфейса (1px solid) */
  --border-strong: #18181B;    /* Активный фокус, выделенный узел (1.5px - 2px solid) */

  /* Текст */
  --text-primary: #141413;     /* Основной текст, названия узлов */
  --text-secondary: #57534E;   /* Метаданные, подписи колонок */
  --text-muted: #8A8680;       /* Вспомогательные индексы, координаты */

  /* Семантическая кодировка источников рёбер (Критично для отладки) */
  --edge-ast: #15803D;         /* Детерминированный AST (зелёный) */
  --edge-config: #0369A1;      /* Конфиги, роутинг, БД (инженерный синий) */
  --edge-ml: #B45309;          /* ML Link Prediction (янтарный/охра) */
  --edge-transitive: #71717A;  /* Транзитивные связи (серый пунктир) */
  --alert-blast: #B91C1C;      /* Радиус поражения / критическая зависимость (красный) */
}

```

## 4. Типографика

Никаких декоративных шрифтов и маркетинговых заголовков. Вся типографика подчинена читаемости идентификаторов сервисов, путей файлов и числовых метрик.

* **Интерфейсный шрифт (`--font-sans`):** `"IBM Plex Sans"`, `"Geist Sans"` или системный гротеск. Используется для заголовков панелей, кнопок и меток фильтров.

* **Технический шрифт (`--font-mono`):** `"JetBrains Mono"` или `"IBM Plex Mono"`. Обязателен для:

  * Идентификаторов сервисов и таблиц БД (`ts-order-service`, `orders_db`).

  * Путей к файлам и номеров строк (`OrderServiceImpl.java:154`).

  * Шаблонов URL и HTTP-методов (`POST /api/v1/orderservice/order/*`).

  * Всех числовых показателей, вероятностей и метрик (`font-variant-numeric: tabular-nums`).

* **Размерная сетка:**

  * Базовый текст таблиц и инспектора: `12px` (`line-height: 1.4`).

  * Заголовки секций: `11px`, `uppercase`, `font-weight: 600`, `letter-spacing: 0.05em`.

  * Метки внутри узлов графа: `11px` моноширинный.

## 5. Конструктивные инварианты и запреты (Anti-Slop Rules)

При генерации или правке кода интерфейса действуют жёсткие ограничения:

1. **Геометрия углов:**

   * Все панели, таблицы, инпуты, кнопки и узлы графа имеют строго `border-radius: 0px` (`rounded-none`).

   * Единственное исключение: компактные текстовые теги HTTP-методов (`GET`, `POST`) допускают `border-radius: 2px`.

   * **Запрещены:** `rounded-md`, `rounded-lg`, `rounded-xl`, `rounded-2xl`, `rounded-full`.

2. **Тени и эффекты глубины:**

   * Для всех элементов интерфейса `box-shadow: none` (`shadow-none`).

   * Разделение слоёв выполняется исключительно сплошными линиями `1px solid var(--border-hairline)` и сменой тона подложки.

   * **Запрещены:** любые размытые тени (`shadow-sm`, `shadow-lg`, `shadow-xl`) и фильтры размытия фона (`backdrop-blur-*`).

3. **Цветовая гигиена:**

   * **Запрещены:** любые градиенты (`bg-gradient-*`, `bg-clip-text`), декоративные цветные пятна на фоне и стандартная фиолетово-индиговая палитра (`indigo-*`, `purple-*`, `violet-*`).

   * Цвет в интерфейсе несёт только семантическую нагрузку (тип узла, источник ребра, статус достижимости).

4. **Плотность данных:**

   * Запрещены крупные внутренние отступы (`p-8`, `p-10`, `gap-8`). Стандартный шаг отступов внутри панелей — `8px` (`p-2`) и `12px` (`p-3`). Высота строки в реестре рёбер — `28px–32px`.

## 6. Визуальная нотация графа (Graph Visual Grammar)

Чтобы граф из 40+ микросервисов и таблиц читался мгновенно, вводится единая геометрия узлов и линий:

### 6.1. Узлы (Nodes)

* **Микросервис (`SERVICE`):** прямоугольник с белой заливкой `#FFFFFF`, рамкой `1.5px solid #18181B`, внутри — моноширинный ID сервиса и бейдж языка (`JAVA`, `GO`, `PY`, `NODE`).

* **Таблица БД (`DB_TABLE`):** прямоугольник с заливкой `#EFEDE8`, двойной левой границей `4px solid var(--edge-config)` и префиксом `[DB]`.

* **Очередь / Топик (`MESSAGE_QUEUE`):** прямоугольник со штриховой рамкой `1.5px dashed #18181B` и префиксом `[MQ]`.

* **Выделенный узел / Эпицентр Blast Radius:** рамка `2px solid var(--alert-blast)` и заливка `#FEF2F2`.

### 6.2. Рёбра (Edges)

* **`AST_EXACT`:** сплошная линия `1.5px`, цвет `var(--edge-ast)`.

* **`CONFIG` / `DB_ACCESS`:** сплошная линия `1.5px`, цвет `var(--edge-config)`.

* **`ML_PREDICTED`:** штриховая линия `1.5px` (`stroke-dasharray: 4 2`), цвет `var(--edge-ml)`, с подписью вероятности (например, `0.84`) на изломе.

* **`TRANSITIVE`:** тонкая пунктирная линия `1px` (`stroke-dasharray: 2 3`), цвет `var(--edge-transitive)`, по умолчанию скрыта чекбоксом в верхней панели, чтобы не замусоривать укладку.

## 7. Интерактивные сценарии (User Flows для демо)

1. **Инспекция доказательств (Evidence Check):**
   Клик по любому ребру на графе или в таблице открывает в правой панели точную карточку `evidence.json`: какой файл и строка кода породили вызов, через какое правило или скор модели была проведена связь.

2. **Калибровка порога уверенности в реальном времени:**
   Перемещение ползунка $p_{\text{threshold}}$ мгновенно скрывает или проявляет жёлтые штриховые рёбра от ML-модели, позволяя глазами увидеть границу, где модель начинает добавлять шум.

3. **Симуляция отказа / изменения (Blast Radius Mode):**
   Переключатель `Режим: Blast Radius` при клике на узел $C$ приглушает весь остальной граф (`opacity: 0.2`) и ярко-красным цветом подсвечивает всю цепочку узлов $A \to B \to C$, которые будут затронуты при изменении $C$, выводя список задетых сервисов в правую панель.

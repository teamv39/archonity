# Справочник архитектурных маркеров и паттернов бенчмарка Train Ticket

> **Устарело.** Написано до выхода пакета участника, под задачу глобального графа сервисов. Действующий пайплайн — [ADR-005](../adr/adr-005_scenario_execution_pipeline.md), правила разметки — [annotation_rules.md](../annotation_rules.md). Внимание: здесь `ts-travel2-service` и `ts-admin-*` названы мёртвым кодом — это неверно (travel2 обслуживает обычные поезда, S6 целиком админский).

Аналитический справочник содержит нормативные таблицы маркеров версий, каталогов HTTP-клиентов и внешних эталонных датасетов для статического анализатора Archonity в соответствии со стандартами [ADR-001](../adr/adr-001_data_contracts_and_system_architecture.md) и [ADR-004](../adr/adr-004_hybrid_recovery_pipeline_and_arbitration.md).

## 2. Каталог паттернов RestTemplate и построения URL

### 2.1. Сводная таблица 3 групп методов RestTemplate в Train Ticket

Межсервисный транспорт Java-компонентов Train Ticket построен исключительно на `org.springframework.web.client.RestTemplate`. Декларативный Feign и реактивный WebClient в сервисах не используются.

| Группа методов | Сигнатура метода в `RestTemplate` | HTTP-метод | Назначение в Train Ticket | Пример вызова в кодовой базе | Правила извлечения фактов в `archparse` (JavaParser & Spoon) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **1. `exchange`** | `<T> ResponseEntity<T> exchange(String url, HttpMethod method, HttpEntity<?> requestEntity, ParameterizedTypeReference<T> responseType, Object... uriVariables)` | Явно задается вторым аргументом (`HttpMethod.POST`, `HttpMethod.GET`, `HttpMethod.DELETE`, `HttpMethod.PUT`) | Сценарии с передачей HTTP-заголовков (`Authorization: Bearer <token>`), произвольных HTTP-глаголов и сохранением generic-типов ответа. | `ts-preserve-service` -> `ts-seat-service` (`/api/v1/seatservice/seats`) | • `URL` = аргумент 0<br>• `HTTP Method` = аргумент 1 (`HttpMethod`)<br>• `Request DTO` = тип полезной нагрузки из `requestEntity.getBody()`<br>• `Response DTO` = generic-аргумент `ParameterizedTypeReference<T>`<br>• `URI Variables` = аргументы 4+ (при наличии) |
| **2. `postForObject` / `postForEntity`** | `postForObject(String url, Object request, Class<T> responseType, Object... uriVariables)`<br><br>`postForEntity(String url, Object request, Class<T> responseType, Object... uriVariables)` | `POST` (неявно) | Служебные вызовы создания/модификации без кастомных заголовков или передача простых структур; возврат сырого объекта `Response.class` или `ResponseEntity`. | `ts-order-service` -> `ts-station-service` (`/api/v1/stationservice/stations/idlist`) | • `URL` = аргумент 0<br>• `HTTP Method` = `POST`<br>• `Request DTO` = аргумент 1 (`request`)<br>• `Response DTO` = аргумент 2 (`responseType`)<br>• `URI Variables` = аргументы 3+ (varargs) |
| **3. `getForObject` / `getForEntity`** | `getForObject(String url, Class<T> responseType, Object... uriVariables)`<br><br>`getForEntity(String url, Class<T> responseType, Object... uriVariables)` | `GET` (неявно) | Прямое чтение сущностей по идентификатору или списка параметров без тела запроса (`requestEntity = null`). | `ts-security-service` -> `ts-order-service` (`/api/v1/orderservice/order/{orderId}`) | • `URL` = аргумент 0<br>• `HTTP Method` = `GET`<br>• `Request DTO` = `null`<br>• `Response DTO` = аргумент 1 (`responseType`)<br>• `URI Variables` = аргументы 2+ (varargs) |

### 2.2. Таблица 4 способов сборки целевых URL

| Способ сборки URL | Представление в AST (JavaParser / Spoon) | Пример в коде Train Ticket | Алгоритм разрешения в Archonity |
| :--- | :--- | :--- | :--- |
| **1. Конкатенация через оператор `+` с `getServiceUrl`** | `BinaryExpr` (`Operator.PLUS`) в JavaParser / `CtBinaryOperator` (`BinaryOperatorKind.PLUS`) в Spoon.<br>Левый лист: вызов `getServiceUrl(...)`, средний: строковый литерал пути, правый: переменная или вызов геттера. | `getServiceUrl("ts-order-service") + "/api/v1/orderservice/order/" + orderId` | 1. Найти узел `getServiceUrl(serviceName)` и извлечь целевой сервис из строкового литерала аргумента.<br>2. Заменить динамические узлы (`NameExpr`, `MethodCallExpr` / `CtVariableRead`, `CtInvocation`) на regex `[^/]+`.<br>3. Сопоставить полученный параметризованный путь с аннотациями `@RequestMapping` целевого контроллера. |
| **2. Шаблоны URI с переменными `uriVariables`** | `StringLiteralExpr` в JavaParser / `CtLiteral` в Spoon с плейсхолдерами вида `{paramName}`. Динамические аргументы передаются в varargs метода `RestTemplate`. | `restTemplate.getForObject("http://ts-user-service:12342/api/v1/userservice/users/{userId}", Response.class, userId)` | 1. Распарсить строковый литерал шаблона URI.<br>2. Извлечь имя целевого хоста и порт из схемы URI.<br>3. Плейсхолдеры `{paramName}` транслировать в regex-группы `([^/]+)` и связать с аргументами varargs и параметрами `@PathVariable` контроллера. |
| **3. Внедрение параметров конфигурации `@Value` с fallback** | `FieldDeclaration` с аннотацией `@Value` в JavaParser / `CtField` в Spoon. Значение задается строковым выражением SpEL с разделителем двоеточия `${property.key:defaultValue}`. | `@Value("${station.service.url:http://ts-station-service:12345}") private String stationServiceUrl;`<br>`String url = stationServiceUrl + "/api/v1/stationservice/stations";` | 1. Распарсить выражение аннотации `@Value`.<br>2. Выполнить поиск ключа в `application.yml` / `bootstrap.yml`; если ключ отсутствует — использовать fallback-значение после двоеточия.<br>3. Провести межпроцедурный анализ потока констант и связать поле с аргументом вызова `RestTemplate`. |
| **4. Цепочки построителя `UriComponentsBuilder`** | Цепочка вызовов fluent interface (`MethodCallExpr` в JavaParser / `CtInvocation` в Spoon): `.fromHttpUrl(...)` -> `.path(...)` -> `.queryParam(...)` -> `.build().toUriString()`. | `UriComponentsBuilder.fromHttpUrl(getServiceUrl("ts-route-service")).path("/api/v1/routeservice/routes").queryParam("from", fromId).build().toUriString()` | 1. Извлечь базовый хост/сервис из аргумента вызова `.fromHttpUrl(...)`.<br>2. Конкатенировать аргументы всех вызовов `.path(...)` цепочки.<br>3. Параметры `.queryParam(...)` сохранить для валидации параметров контроллера (`@RequestParam`). |

### 2.3. Распаковка обобщенного типа `ParameterizedTypeReference<Response<T>>`

В Train Ticket полезная нагрузка ответов стандартизирована классом `edu.fudan.common.util.Response<T>` (`int status`, `String msg`, `T data`).

| Аспект generic-десериализации | Описание проблемы стирания типов (Type Erasure) | Решение в коде (Super Type Token) | Правило извлечения контракта для `archparse` |
| :--- | :--- | :--- | :--- |
| **Одиночный DTO:** `Response<T>` | Вызов `restTemplate.postForObject(url, req, Response.class)` стирает метаданные типа поля `data`. Jackson десериализует его в сырой `LinkedHashMap`, вызывая `ClassCastException` в runtime. | Передача анонимного класса `new ParameterizedTypeReference<Response<TripAllDetail>>() {}`. Компилятор фиксирует generic-сигнатуру в байткоде родительского класса (`TypeCapture`). | 1. `archparse` находит узел создания анонимного класса, реализующего `ParameterizedTypeReference`.<br>2. Извлекается тип первого аргумента generic-дескриптора: `Response<T>`.<br>3. Извлекается вложенный тип `T` (`TripAllDetail`, `Ticket`, `Order`).<br>4. Структура полей класса `T` сопоставляется с возвращаемым DTO эндпоинта поставщика. |
| **Коллекция DTO:** `Response<List<T>>` / `Response<ArrayList<T>>` | Двойное стирание типов: стирается как тип контейнера ответа `Response`, так и параметризация коллекции `List<T>`. Сырая десериализация приводит к `ArrayList<LinkedHashMap>`. | Передача вложенного generic-токена: `new ParameterizedTypeReference<Response<List<Station>>>() {}`. | 1. `archparse` рекурсивно раскручивает цепочку generic-аргументов: `ParameterizedType` -> `Response` -> `List` -> `Station`.<br>2. В качестве целевого DTO данных извлекается тип элемента коллекции `T` (`Station`, `Trip`, `Route`).<br>3. Фиксируется арность ответа (`cardinality: "MANY"`). |

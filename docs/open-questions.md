## <a id="oq-05"></a> OQ-05. Модели: эмбеддинги, LLM и рантайм

Нужно: модель эмбеддингов для второго ретривера M1; локальная LLM для заземления шагов и судьи.

**LLM — решено 17.10.** `Qwen3.6-35B-A3B` (GGUF `UD-IQ4_XS`) на llama.cpp, часть экспертов в RAM. Требование NVFP4 снято. Причины и замер скорости — в [исследовании](researches/model_selection.md), запись в «Модель и железо» ADR-005.

**Эмбеддинги — открыто.** Кандидаты: `Qwen3-Embedding-4B` и `EmbeddingGemma 2`.

Что проверить:

- бейкофф эмбеддингов (Recall@k по парам «шаг — обработчик») и сравнение с BM25 и RRF;
- качество LLM на шагах S0 (5 эталонных входов) и на ручной сверке входов S1–S7: верные обработчики, валидность JSON, параметры;
- вердикты судьи на путях S0 с однозначной веткой.

Итог по эмбеддингам записать в раздел «Модель и железо» ADR-005.

## <a id="oq-06"></a> OQ-06. Отчёт платформы

Если платформа показывает IoU по видам рёбер и сценариям, абляции можно делать точечно. Если только общий балл — правила проверяем пачками и чаще смотрим на S0.

## <a id="oq-08"></a> OQ-08. Шаги без явного действия

«Open the new order», «Check the price of the order», «Take the first contact» — по условию каждый шаг даёт один запрос, но какой именно, нужно найти в `ts-ui-dashboard` (страницы `client_order_list`, `client_ticket_book`). Решаем при ручной сверке входов 17.10.

## <a id="oq-09"></a> OQ-09. Асинхронный код и внешняя оплата

- В S4 оплата идёт через внешний канал: какой путь в `ts-inside-payment-service` и `ts-payment-service`.
- `AsyncTask#sendAsyncCallToPaymentService` вызывает внешний адрес без `remote_call` — исполняется ли метод и попадает ли в `executes`.
- `@Async` и потоки (`PollThread` в `ts-wait-order-service`) — относятся ли к сценарию.

## <a id="oq-10"></a> OQ-10. Когда удалять старый код

Предложение: `engine/`, `tests/`, `run_eval.py`, `facts/`, `data/`, `output/` удалить отдельным PR, когда новое ядро даст балл на S0 не ниже `baseline_nlp.py`. До этого они не мешают.

## Закрытые вопросы

- **OQ-01. Формат evidence.json.** Словарь по ключу ребра сохраняется, формат обновлён (evidence v2 в ADR-005).
- **OQ-02. Формат скелета.** Известен из пакета участника: `nodes` — словарь ID → вершина, `edges` — список `{source, type, target}`. Слой адаптеров сохраняется.
- **OQ-03. Разрывы call graph.** Неактуально: связи берём из скелета и IR, вопрос стал вопросом о ветвлениях (ADR-005, M4).
- **OQ-04. Транзитивное замыкание.** Неактуально: ответ — рёбра исполнения, транзитивных рёбер в нём нет.
